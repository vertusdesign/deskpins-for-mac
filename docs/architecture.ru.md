# DeskPins for macOS

Закрепление любого окна поверх остальных — аналог [DeskPins](https://deskpins.com/) для Windows.
Живёт в строке меню, без иконки в Dock, без зависимостей.

- **Закрепить активное окно** — глобальный хоткей (по умолчанию ⌃⌥⌘P) или пункт меню;
  повторный вызов открепляет
- **Открепить** — клик по зелёной булавке в углу окна, или через меню
- Меню в строке меню показывает список всех закреплённых окон
- **Настройки** (⌘,) — переназначение и отключение хоткея, автозапуск при входе
- **Язык** — подменю с 16 языками

Нужны два разрешения: **Универсальный доступ** и **Запись экрана** (почему — ниже).

## Языки

Английский — язык по умолчанию и фолбэк для любой строки, которой нет в таблице
выбранного языка. Английский и українська идут первыми, остальные отсортированы по
самоназванию: так язык проще найти глазами, не зная, как он называется по-английски.

English · Українська · العربية · Deutsch · Ελληνικά · Español · Français · हिन्दी ·
Italiano · 日本語 · 한국어 · Polski · Português · Türkçe · Tiếng Việt · 中文（简体）

Строки лежат в `L10n.swift` таблицами в коде, а не в `.lproj`: приложение позволяет
выбрать язык вручную независимо от системного, а бандл собирается скриптом, без Xcode.

Арабский подключён, но интерфейс не переворачивается справа налево — текст рендерится
корректно, выравнивание пунктов меню остаётся левым.

## Сборка

Один раз — создать локальный сертификат подписи (зачем — ниже):

```bash
./Scripts/create-signing-cert.sh
```

Дальше сборка и установка в `/Applications`:

```bash
./Scripts/build-app.sh --install
```

Без `--install` бандл остаётся в `build/DeskPins.app`.

При первом закреплении приложение попросит разрешения
(Системные настройки → Конфиденциальность и безопасность). После выдачи DeskPins нужно
перезапустить — macOS не применяет новые разрешения к уже запущенному процессу.

### Почему нужен сертификат подписи

Без него разрешения приходится выдавать заново после каждой пересборки, вручную удаляя
устаревшую запись из Системных настроек.

Причина в том, чем TCC опознаёт приложение — в designated requirement. У ad-hoc подписи
(`codesign --sign -`) нет ни сертификата, ни Team ID, поэтому опознавать нечем, кроме хеша
самого бинарника:

```
designated => cdhash H"dd27e9e4628799773fdcc285021c73d7ef674144"
```

Любая правка кода меняет хеш → выданное разрешение перестаёт соответствовать приложению.
Строка в списке при этом остаётся: имя и путь не изменились, и выглядит она рабочей,
хотя ни на что не влияет.

С локальным сертификатом requirement называет подписанта, а не байты:

```
designated => identifier "com.deskpins.mac" and certificate leaf = H"06aa4961…"
```

Проверено: правка кода меняет cdhash (`d7ef0cb2…` → `43a2688d…`), requirement остаётся
прежним. Разрешения выдаются один раз и переживают пересборки.

Сертификат самоподписанный и используется только локально. Доверенным его делать не нужно —
`codesign` принимает его как есть, а Gatekeeper к собранному вами приложению не применяется.
Удалить: Связка ключей → login → «DeskPins Local Signing».

Если вы меняете сертификат или переходите с ad-hoc — старые записи TCC надо сбросить один раз:

```bash
tccutil reset Accessibility com.deskpins.mac && tccutil reset ScreenCapture com.deskpins.mac
```

### Прочие особенности сборки

Обе учтены в скрипте:

- **База сборки вынесена в `~/Library/Caches/DeskPins-build`.** SwiftPM внутри `~/Documents`
  падает с `accessing build database … disk I/O error` — компиляция проходит, но линковка
  не выполняется и бинарник не появляется. Переопределяется через `DESKPINS_SCRATCH`.
- **Собирается только под архитектуру хоста.** Universal binary (`--arch arm64 --arch x86_64`)
  требует полного Xcode: с одними Command Line Tools SwiftPM сообщает, что нет `xcbuild`.
  Скрипт пробует universal и молча откатывается на host-only.

## Как это устроено

На Windows DeskPins — это одна строчка `SetWindowPos(hwnd, HWND_TOPMOST, …)`: система
разрешает менять z-порядок чужого окна.

**В macOS z-порядок обычных окон приложение-центричный.** Окна активного приложения всегда
выше окон всех неактивных — это свойство системы, а не настройка конкретного окна.
Публичного API, позволяющего поднять чужое окно над активным приложением, нет:
`NSWindow.level` применим только к собственным окнам, а Accessibility API даёт позицию,
размер и `AXRaise`, но не уровень окна. `AXRaise` переставляет окно лишь внутри его
собственного приложения — над активным приложением он его не поднимет никогда.

Поэтому «поверх всех» здесь делается **зеркалом**:

1. Своя панель (`NSPanel`, уровень `.floating`) — наше окно, ему уровень задать можно.
2. В неё транслируется живое содержимое чужого окна через ScreenCaptureKit.
3. Панель держится ровно поверх оригинала: события перемещения и изменения размера
   приходят от `AXObserver`.
4. Пока приложение-владелец само активно, зеркало выключается — реальное окно и так
   наверху, и вы работаете с ним напрямую.
5. Клик по зеркалу активирует приложение-владельца и поднимает настоящее окно.

Практические следствия:

- Нужно разрешение **«Запись экрана»** — без него зеркало не запустится.
- Зеркало — картинка, а не окно. Клик по нему переключает вас на настоящее окно
  (одним кликом), после чего вы работаете с оригиналом.
- Панель имеет `.fullScreenAuxiliary`, поэтому закреплённое окно видно в том числе
  поверх полноэкранных приложений.

### Что было отвергнуто

**`AXRaise` по событиям** (первая версия). Приложение переподнимало закреплённое окно при
каждой активации другого приложения. Не работает по причине выше: поднять окно над окнами
активного приложения `AXRaise` не может — окно исправно поднималось внутри своего
приложения и оставалось под чужими окнами.

**Приватные SkyLight API** (`SLSSetWindowLevel`). Даёт настоящий topmost с нулевой
нагрузкой, но чтобы менять уровень чужого окна, нужен привилегированный доступ к
window server: на практике это инжект в Dock.app и частично отключённый SIP (путь yabai).
Ломается при обновлениях macOS. Для утилиты общего пользования не подходит.

## Энергоэффективность

Ничего не опрашивается по таймеру. Всё построено на событиях:

- `AXObserver` — перемещение, изменение размера, сворачивание, закрытие окна
- `NSWorkspace` — активация приложения, завершение приложения, смена Space

Захват экрана — самая дорогая часть, поэтому он ограничен:

- Стрим существует **только пока зеркало видимо**; как только приложение-владелец
  становится активным, `stopCapture` полностью его гасит.
- ScreenCaptureKit присылает кадр только при изменении содержимого — статичное окно
  не стоит почти ничего. Кадры со статусом `.idle`/`.blank` отбрасываются.
- Кадр отдаётся слою как `IOSurface` напрямую — без `CIContext`, `CGImage` и
  аллокаций на кадр.

Без закреплённых окон — 0% CPU, 23,5 МБ RSS.

## Детали реализации

**Скругление зеркала.** Публичного API для радиуса скругления окон нет, поэтому
`SystemMetrics` создаёт временное окно и спрашивает у его frame view значение
`cornerRadius` — то же, которым система рисует настоящие окна. На macOS 26.5 это `16.0`.
Каждый шаг защищён проверками, при отсутствии ключа берётся константа по версии ОС.
Слой зеркала использует `cornerCurve = .continuous` — ту же «squircle»-кривую, что и AppKit.

**Хоткей.** Хранится виртуальный код клавиши, а не символ, поэтому сочетание переживает
смену раскладки; для показа символ запрашивается у текущей раскладки через `UCKeyTranslate`.
Регистрация — Carbon `RegisterEventHotKey`, а не event tap: это принципиально, потому что
event tap видел бы все нажатия в системе и требовал бы разрешения «Мониторинг ввода».
В рекордере ⎋ отменяет запись, ⌫ выключает хоткей, сочетание без модификатора отвергается.

**Маркер при перетаскивании.** Accessibility сообщает о каждом шаге перетаскивания, но не
сообщает о его окончании. Поэтому на первом же событии перемещения булавка гасится быстрым
фейдом (0,1 с) и вообще не позиционируется, пока окно едет, а возвращается (0,12 с) по
отпусканию кнопки мыши — его ловят глобальный и локальный мониторы `NSEvent`. Окно можно
двигать и без мыши (с клавиатуры, через Stage Manager, из другого приложения), поэтому есть
подстраховка: если движение прекратилось и мышь не отпускали, булавка возвращается через
0,4 с простоя. Позиция пересчитывается один раз, уже на новом месте окна.

**Когда зеркало включено.** Не «пока чужое приложение впереди», а «пока пользователь не
работает именно в этом окне». Активным считается окно, чьё приложение впереди и которое
это приложение само держит в фокусе (`AXFocusedWindow`). Поэтому если поднять другое окно
того же приложения, закреплённое перестаёт быть активным и его зеркало выходит наверх —
иначе соседнее окно Finder перекрывало бы закреплённое.

Смену фокуса внутри приложения сообщает `AXObserver`, подписанный на элемент приложения
(`kAXFocusedWindowChangedNotification`), а не на окно.

**Уровни окон.** Зеркало неактивного пина — `.floating` (слой 3), зеркало активного —
`.floating + 1` (слой 4), булавка — `.floating + 2` (слой 5). Благодаря этому выбранное
закреплённое окно оказывается над остальными закреплёнными, а не под ними.

У активного пина зеркало кликопрозрачное (`ignoresMouseEvents`): оно держит своё место в
стопке, но клики, прокрутка и перетаскивание проходят сквозь него в настоящее окно,
лежащее ровно под ним.

Два случая, когда зеркало активного окна не нужно и выключается ради экономии: закреплено
одно окно (перекрывать нечего) и окно перетаскивают (картинка отставала бы от настоящего
окна).

**Mission Control и Spaces.** Зеркало и булавка объявлены `.transient` — этот флаг прямо
означает «прячется в Exposé», поэтому в Mission Control они не загораживают содержимое.
Раньше стоял `.stationary`, который делает ровно обратное: держит окно поверх Exposé.
Флаги взаимоисключающие, AppKit оставляет последний.

Флага `.transient` мало: панели всё равно видны на других рабочих столах, потому что
`.canJoinAllSpaces` показывает их везде. Поэтому видимость определяется явно — через
`CGWindowListCopyWindowInfo` с `optionOnScreenOnly`, который перечисляет только окна
текущего Space. Если ID закреплённого окна там не нашёлся, окно осталось на другом столе,
и его зеркало вместе с булавкой прячутся.

Отдельная и куда менее очевидная проблема — возврат на стол с закреплёнными окнами.
`AXRaise`, вызванный для окна, которое живёт на другом Space, заставляет macOS туда
перепрыгнуть. При переходе на новый стол меняется активное приложение, срабатывал
обработчик активации и поднимал закреплённое окно — систему утаскивало обратно. Отсюда и
зависимость от количества пинов: чем их больше, тем вероятнее, что новое активное
приложение окажется владельцем одного из них. Теперь `raiseWithinApp` вызывается только
для окна, находящегося на текущем Space.

**Открытие зеркала без анимации.** У панели `animationBehavior` по умолчанию `.default`,
что для панели означает анимацию служебного окна — она читалась как «всплывание» зеркала
на месте настоящего окна. Выставлено `.none`.

**Автозапуск.** `SMAppService.mainApp` — штатный путь начиная с macOS 13, без хелпер-бандла
и без plist в `LoginItems`. По умолчанию выключен. Если пользователь отключил пункт сам,
приложение не может включить его обратно и открывает Системные настройки.

## Безопасность

DeskPins держит два самых мощных разрешения в macOS — «Универсальный доступ» и «Запись
экрана». Поэтому что именно он с ними делает, проверялось отдельно.

**Что приложение делает с правами.** Через Accessibility — только читает позицию, размер и
заголовок окна и вызывает `AXRaise`. Ни ввода текста, ни чтения содержимого полей, ни
управления чужими элементами. Через ScreenCaptureKit — захватывает не экран, а конкретное
окно (`SCContentFilter(desktopIndependentWindow:)`), кадр уходит прямо в слой и нигде не
сохраняется, не кодируется и не передаётся.

**Проверено по бинарнику:**

- Ни одного сетевого символа и ни одного сетевого фреймворка. Приложение не умеет
  выходить в сеть в принципе.
- Нет `NSTask`, `posix_spawn`, `dlopen` — приложение не запускает сторонний код.
- Нет `CGEventTap`/`CGEventPost` — клавиатуру и мышь оно не слушает и не подделывает.
  Глобальный хоткей сделан на Carbon, который сообщает только о своём сочетании.
- Нет entitlements, URL-схем, XPC-сервисов и слушающих сокетов — внешней поверхности атаки нет.
- Данные на диске: только `UserDefaults` (язык, хоткей). Ничего чувствительного.

**Найдено и исправлено.**

1. *Hardened runtime был выключен* (`flags=0x0(none)`). Без него не работает library
   validation, и любой процесс, запущенный от имени пользователя, мог внедрить свою
   библиотеку в DeskPins и унаследовать его разрешения TCC — то есть получить доступ к
   Accessibility и записи экрана в обход собственного запроса. Проверено практически:
   `DYLD_INSERT_LIBRARIES` успешно внедрялся. Исправлено добавлением `--options runtime`
   при подписи; после этого внедрение блокируется (контрольный прогон без hardening
   подтверждает, что проверка не даёт ложноотрицательный результат).
2. *Маркер булавки жил на уровне `.screenSaver`* (1000) — то есть поверх системного
   интерфейса и заставки. Опущен до `.floating + 1`: выше зеркала и не выше.

**Остаточные риски, о которых стоит знать.**

- *Закреплённое окно видно всегда.* Это и есть функция, но следствие такое: если закрепить
  окно менеджера паролей или переписки, его содержимое остаётся на экране при переключении
  на другое приложение и поверх полноэкранных приложений. Экран блокировки зеркало
  перекрывает — оно на уровне `.floating`, намного ниже.
- *Ключ подписи доступен без подтверждения.* Сертификат импортирован с `-A`, то есть любой
  процесс пользователя может подписать им код. Само по себе это не даёт злоумышленнику
  ничего нового — ему уже нужно выполнение кода от вашего имени, — но подписанный этим
  ключом бинарник унаследовал бы разрешения DeskPins. Если хочется строже: удалить
  сертификат и переимпортировать без `-A`, либо держать его в отдельной связке ключей с
  паролем. Цена — запрос подтверждения при каждой сборке.
- *Приложение не нотаризовано.* Для локальной сборки это нормально, но раздавать такой
  бандл нельзя: у другого пользователя Gatekeeper его заблокирует, и это правильное
  поведение. Для распространения нужен Developer ID и нотаризация.
- */Applications доступна на запись администратору.* Подмена бандла возможна, но подменённый
  бинарник не унаследует разрешения: designated requirement требует именно ваш сертификат.

## Статус

Проверено сквозным прогоном через Accessibility: срабатывание глобального хоткея ⌃⌥⌘P,
закрепление активного окна, появление зеркала (920×492) и маркера (22×22) на экране,
«Открепить всё», открытие окна настроек, наличие кнопки «Restore Default» и её
неактивность при хоткее по умолчанию.

Поднятие настоящего окна при откреплении проверено отдельно: закреплено окно Finder,
фокус уведён на TextEdit (зеркало активно, два окна DeskPins на экране), затем откреплено
через меню — активным стал Finder, окон DeskPins осталось 0.

Флаги окон проверены замером в отдельном процессе: `.transient` применяется и вытесняет
`.stationary`, `animationBehavior` меняется с `.default` (0) на `.none` (2).

Перекрытие соседним окном приложения: закреплено окно Finder «Applications» — окон DeskPins
на экране 1 (только булавка, зеркало выключено); поднято окно «Documents» — стало 2,
зеркало вышло наверх.

Уровни окон при двух закреплённых окнах, замер через `CGWindowListCopyWindowInfo`:

