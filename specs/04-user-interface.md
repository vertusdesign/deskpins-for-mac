# 04 — User interface

## U-1 Status item

An `NSStatusItem` of variable length showing the `pin.fill` SF Symbol as a template image,
so it follows the menu-bar appearance. Transient feedback (no window found, permission
missing) is shown by briefly setting the button's title for 1.6 s rather than posting a
notification.

## U-2 Menu

Order, top to bottom:

1. **Pin Frontmost Window** — shows the current global shortcut as its key equivalent
2. separator
3. **Pinned** header, then one item per pinned window, each with a checkmark and a
   "click to unpin" tooltip; or **No Pinned Windows** (disabled) when there are none
4. **Unpin All** (only when at least one window is pinned)
5. separator
6. **Language** ▸ submenu — **MUST** carry the `globe` SF Symbol. A user who cannot read the
   current language needs a way to recognise this item; the icon is that way.
7. **Launch at Login** — checkbox reflecting `SMAppService` status
8. **Settings…** — ⌘,
9. separator
10. Permission warnings, when any permission is missing, each opening the relevant System
    Settings pane
11. **About DeskPins for Mac**
12. **Quit DeskPins for Mac** — ⌘Q

Pinned window titles are truncated to 44 characters. Each is labelled
`Application — Window title`, falling back to the application name alone when the window has
no title.

## U-3 Pin badge

A 22 × 22 non-activating borderless panel over the pinned window's top-right corner.

- A disc filled with a vertical gradient from `sRGB(0.64, 0.86, 0.38)` to
  `sRGB(0.36, 0.68, 0.20)` — light at the top so the white glyph keeps contrast.
- A soft drop shadow below, and a 1 pt white rim at 55 % opacity so the badge stays readable
  on light window content.
- The `pin.fill` SF Symbol in white, bold, centred.
- Clicking it unpins (B-17).
- Non-activating: showing it never takes focus from the window it decorates.

## U-4 Application icon

Generated by `Scripts/make-icon.swift` from the same drawing, so it cannot drift from the
badge: the same gradient disc and white pin, inset by 9 % of the canvas, glyph at 36 % of
the canvas, rendered at all ten sizes and packed with `iconutil`.

The icon is generated during the build. There is no binary asset in the repository.

## U-5 Settings window

Titled, closable, not resizable. Contains:

- **Global shortcut:** label and a shortcut recorder
- A hint line: what the shortcut does and that ⌫ disables it
- **Restore Default** — stays in place but is disabled while the default is already in use,
  so the row never jumps
- **Launch at Login** checkbox

Opened with ⌘, or from the menu. Re-reads every string when the language changes.

## U-6 Shortcut recorder

- Click to arm; the border switches to the accent colour and the field reads "Press keys…".
- ⎋ cancels. ⌫ or ⌦ clears the shortcut, which disables it.
- A combination with no modifier is rejected with a beep — it could not be registered
  globally.
- Recording MUST suspend the registered hot key, otherwise the existing combination fires
  instead of being recorded.
- `performKeyEquivalent` must be overridden as well as `keyDown`, or combinations like ⌘Q
  never reach the control.
- Losing key focus or closing the window cancels recording.
- Displays as `⌃⌥⇧⌘` in that order followed by the key name, resolved through the current
  keyboard layout (see [05](05-localization.md) and `Shortcut.swift`).

## U-7 About window

Centred column: application icon at 96 pt, display name, `Version 0.9.0 (alpha)` read from
the bundle, one-line description, the alpha notice, a separator, then:

- **Inspired by DeskPins for Windows** — links to <https://deskpins.com/>
- a row of links: Source code, Terms of Use, Privacy Policy, Disclaimer
- `MIT License · © 2026 DeskPins for Mac contributors`

Links are borderless buttons with underlined link-coloured titles and the URL as tooltip;
each MUST expose an accessible title. The window is rebuilt on each open so a language
change is reflected.

## U-8 Permission prompting

The application MUST NOT display its own alert about missing permissions (B-4). It triggers
the system dialog, shows a warning row in the menu that opens the right System Settings
pane, and briefly labels the status item.

**U-8.1** Both permissions MUST be requested, never only the first one found missing.
Requesting is what registers the app in the System Settings list — an app that never asks
does not appear there, and the user has to add it by hand.

**U-8.2** Two system permission prompts raised in the same instant end with only one of them
on screen. The screen-recording request MUST therefore be deferred when the Accessibility
prompt is also going up.

**U-8.3** macOS shows each permission prompt only the first time. On a later attempt to pin
with a permission still missing, the app MUST open the relevant System Settings pane rather
than fail silently — at that point no system dialog is coming that ours could cover.

**U-8.4** `CGPreflightScreenCaptureAccess` caches its answer for the lifetime of the
process, so it keeps reporting "denied" after the user grants access. A successful
ScreenCaptureKit query is the authority, and remembering it lets the permission take effect
without quitting the app.

## U-9 Appearance

Every colour except the badge gradient comes from a semantic `NSColor`, so light and dark
mode both work without a branch. The badge gradient is deliberately fixed: it must read the
same over arbitrary window content.
